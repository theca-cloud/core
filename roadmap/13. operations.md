# Step 13: Operations

Goal: an instance an admin (or the SaaS app) can run: settings changed live, organizations, accounts and storages managed through the API, abuse slowed down, the server observable, and accounts deletable and exportable.

Design: `../docs/decisions.md` (Configuration, Authentication, Deletion, Licensing and editions: the SaaS app drives the core through the admin API), `../docs/features.md` (Instance admin, Admin API, Brute-force protection, Metrics, GDPR).

**Three parts, each its own branch, squashed into `dev` when green**: they're independent, and three reviews beat one huge one.

## 13a. Admin API and live settings

- **Settings reload live**: `AppState` holds the settings behind a lock (`settings()` returns a snapshot); a write through the API validates (the same parsers as at startup), saves and swaps them. One process: no cross-process notification. Then:
    - `GET /admin/settings` (every key, its value or default, its description), `PATCH /admin/settings` (refused as a whole on any invalid value).
    - **Job intervals become settings** (`job_<name>_interval_secs`), read at each wait.
    - The email job uses the reloaded settings instead of reading the database at each run.
- **Organizations** (`/admin/organizations`): list (owner, members, quota, used bytes, suspended), create (a name and the email of an existing account, its owner), change quota and default storage, **suspend** (`organization.suspended_at`: `organization_access` skips it, so nothing of it is reachable; members still log in and see it suspended), delete (part c).
- **Accounts** (`/admin/accounts`): search by email, make or unmake instance admins (never the last one), **suspend** (`account.suspended_at`: its tokens stop authenticating), delete (part c).
- **Storages** (`/admin/storages`): list, add (probed like the setup's), change the instance default. No deletion while chunks use it.
- **Identity providers**: instance-wide ones by the admin (`/admin/identity-providers`), an organization's by its owner (`/organizations/{id}/identity-providers`). **SSRF guard for organization-configured issuers**: `https` only, and every address the host resolves to must be public (no loopback, private, link-local, CGNAT, metadata ranges), checked at each discovery with the connection pinned to the checked address (no DNS rebinding in between). Instance-wide providers are trusted (the admin can reach the server's network anyway).
- Every admin endpoint: an instance admin, from a full session.

## 13b. Abuse and observability

- **Rate limits**, in memory (one process), fixed windows, `429` with `Retry-After`:
    - login: per IP and per account; TOTP and recovery codes: per account; password reset, verification resend, registration: per IP and per address; the setup token: per IP; invitations: per organization.
    - **Slowing, never locking**: a lockout would let anyone lock a victim out. Limits are settings.
- **The client's IP behind a proxy**: `TRUSTED_PROXIES` (env, CIDRs): `X-Forwarded-For` is followed through them only. Without it, the peer is the client (and behind an undeclared proxy, every client shares its address: documented).
- **Prometheus metrics** (`metrics`, `metrics-exporter-prometheus`) on **a separate listener**, `METRICS_ADDR` (env, off by default), never on the public port:
    - HTTP requests (route template, status, duration), WebDAV requests, bytes uploaded and downloaded through the server;
    - job runs (duration, items, failures), emails sent and given up;
    - anomalies by type (from the `anomaly` field every one already has), rate-limited requests;
    - the database pool (connections in use, waiting).
    - No per-organization or per-account labels (unbounded cardinality); usage per organization is the admin API's.

## 13c. Account deletion and export (GDPR)

- **Deleting an account** (the account itself from a full session with its password or TOTP, or an admin):
    - refused while it **owns a company organization**: ownership is transferred first (`POST /organizations/{id}/owner`, to a joined member) or the organization deleted;
    - its personal organization is deleted (below), its memberships removed (versions keep their content, their author becomes empty), its identities, tokens, sessions and queued emails deleted, then the account.
- **Deleting an organization** (its owner, or an admin): every library, node, version and chunk reference, immediately (decisions.md: GDPR erasure is immediate hard deletion). The chunks then go with the next GC run, triggered right away.
- **Export** (`GET /me/export`, a full session): a JSON document with the account, memberships, sessions, identities (never secrets), app passwords (names and scopes) and the list of files it can reach. The files themselves come through the existing paths (CLI, WebDAV); a ZIP of a personal organization is a later convenience.

## Not in this step

- Audit log, usage history per organization (billing reports are the SaaS app's), per-node permissions (with the RBAC engine).

## Tests

- 13a: a setting changed through the API applies at once (a job interval, the registration toggle); invalid values refused as a whole; a suspended organization unreachable to its members, reachable again when lifted; a suspended account's tokens refused; the last instance admin can't be removed; the SSRF guard refuses `http://`, `localhost`, `10.x`, `169.254.169.254`, and a name resolving to a private address.
- 13b: each limit trips at its threshold with `Retry-After`, per key (another IP or account isn't affected); `X-Forwarded-For` honored only through trusted proxies; the metrics listener serves the counters, the public port doesn't.
- 13c: an account owning a company organization can't be deleted until ownership moves; deletion leaves nothing of the account (identities, tokens, emails, personal organization), versions survive authorless; an organization's deletion leaves no node, and the GC then removes its objects; the export contains no secret.
