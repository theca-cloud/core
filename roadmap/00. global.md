# Global roadmap

From an empty repo to a working V1 core. Each step gets its own detailed file (`01. ...`, `02. ...`). Scope and design: see `../docs` (`features.md` V1 tags, `decisions.md`, `db.md`).

The order front-loads risk: the upload protocol (the hardest part of the design) is proven end to end in step 4, before auth, setup and WebDAV are built on top of it.

## Steps

| # | Step | Done when |
|---|---|---|
| 1 | **Skeleton** | `cargo build` and the Woodpecker pipeline pass |
| 2 | **`common`** | Chunking, hashing, names and compression are unit-tested |
| 3 | **Server foundation** | The server starts, migrates an empty DB, answers `/api/health` |
| 4 | **Vertical slice** | A test uploads a file, downloads it, and gets the same bytes |
| 5 | **Storage backends** | Same test passes on S3 with presigned URLs |
| 6 | **Identity and auth** | A real account logs in and only sees its own libraries |
| 7 | **First-run setup** | A fresh instance is set up through the wizard API |
| 8 | **File operations** | Folders, moves, trash, versions, conflicts and search work |
| 9 | **Background jobs** | GC, trash purge and cleanups run, survive crashes, and are visible to the admin |
| 10 | **Emails** | Verification, password reset and registration work end to end |
| 11 | **WebDAV and streaming** | A WebDAV client mounts a library; the browser previews a video |
| 12 | **`client` library** | The engine uploads, resumes, cancels and downloads against a real server, natively and from WASM in a browser |
| 13 | **Operations** | Rate limiting, metrics, admin API, GDPR export and deletion |
| 14 | **First release** | A multi-arch Docker image is published as `0.1.0` |

## Contents

1. **Skeleton**: Cargo workspace (`common`, `core` as lib + thin bin, `client`), lints, `docker-compose.dev.yml` with Postgres 17, Woodpecker pipeline (fmt, clippy, tests), `LICENSE`, `CONTRIBUTING.md`.
2. **`common`**: FastCDC (512 KiB / 1 MiB / 8 MiB), `xxh3_128`, file name rules (NFC, forbidden characters and names, 255 bytes), LZ4 with the entropy check, shared enums with an `Unknown` fallback.
3. **Server foundation**: env config with `__FILE` secrets, JWT key loaded or generated, first migration, `Settings` (string KV, typed in code), migrations at startup, `/api/health`, `/api/version`, `utoipa` spec generation and `openapi.json` committed from here on.
4. **Vertical slice**: libraries with their root node, nodes, the full upload protocol (lookup, announce, commit, cancel, keepalive), download, on the filesystem backend with a hard-coded user.
5. **Storage backends**: storage table and selection at library creation, `object_store` S3 with batched presigned URLs, quotas, a backend-agnostic test suite (in-memory + MinIO/Garage).
6. **Identity and auth**: organizations, accounts, users, identities (password with Argon2id, OIDC), access JWT and sliding refresh cookies, `token` table, app passwords, TOTP, owner-only authorization.
7. **First-run setup**: wizard API protected by a setup token printed in the logs (env opt-out), creating the admin, the first organization and the first storage backend (credentials as file paths).
8. **File operations**: mkdir, rename, move (no cycles), soft delete and restore, version tree with restore, conflicts and messages, name search (`pg_trgm`).
9. **Background jobs**: tokio loop per job, `job_run` history, admin trigger, GC with tombstones, trash purge, token and invitation cleanup, crash and restart handling.
10. **Emails**: `email` queue with retries, SMTP (`lettre`), `askama` templates (HTML + text), tokens created at send time, self-registration.
11. **WebDAV and streaming**: `dav-server` over nodes and chunks, streaming endpoint with Range support, used for WebDAV and V1 previews.
12. **`client` library**: one engine for every client, web included. Upload (chunk, hash, lookup, batched upload, keepalive, commit, resume, cancel), download (presigned URLs, reassembly), auth, local config, as plain async Rust over a small `Platform` trait (native and WASM implementations). API client generated with `progenitor` from `openapi.json`. WASM npm package with a thin TypeScript API for the web app.
13. **Operations**: rate limiting and brute-force protection, Prometheus metrics, admin API (organizations, quotas, suspension), account deletion and data export.
14. **First release**: release pipeline (`prod` and `dev` tags), multi-arch image, `oasdiff` check against the previous release, published crates and WASM package on the Gitea registries.

## Out of scope for the core V1

Sharing (V2), Service Worker previews (V2), E2EE, change feed and sync, paid features, plugins. See `../docs/features.md`.
