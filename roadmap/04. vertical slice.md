# Step 04: Vertical slice

Goal: prove the upload protocol end to end before building on it. A file is uploaded, deduplicated, committed, and downloaded back identical, on the filesystem backend.

The schema is done (single migration, every constraint tested in `tests/schema.rs`): this step only writes code on top of it.

Design: `../docs/decisions.md` (Upload flow, Trust boundary: library and namespaces, Downloads, Storage backends, Library root folder), `../docs/db.md` (code-checked invariants).

## Temporary authentication

Real auth is step 06. Until then, requests carry **`X-Theca-User: <user uuid>`**, read by a `CurrentUser` extractor (the user and their organization). Handlers only ever use `CurrentUser`, so step 06 replaces the extractor's internals and nothing else. Tests use it to act as several users.

No setup wizard yet (step 07): tests create organizations, users and storages directly in the database.

## Database access

- A `db` module owns every query (`query!` / `query_as!`), so handlers never write SQL.
- Database refusals (named constraints and triggers) are mapped to API errors in one place: e.g. `node_name` → `name_taken`, `library_name` → `library_name_taken`, `chunk_in_version_chunk` → `chunk_missing`.

## Storage backend

- `Backend`: `put`, `get`, `head` (real size), `delete`, presigned upload and download URLs, over `object_store` (`LocalFileSystem` here, S3 in step 05). Built from a `storage` row (`implementation`, `details`).
- **Filesystem presigned URLs**: the server signs its own URLs, `/api/v1/blobs/{chunk uuid}?expires=…&sig=…` (HMAC-SHA256, key derived from the JWT key). The blob endpoints check signature and expiry, then `PUT` (atomic: temp file + rename) or `GET` the object. Same shape as S3 presigning, so clients don't care which backend they talk to.
- Object key = the chunk's `uuid`.

## API (`/api/v1`)

| Endpoint | Does |
|---|---|
| `POST /libraries` | `{name, namespaces}` → creates the library, its root node, and the creator as `write` member. Storage: the organization's default, else the instance default, else error. `namespaces`: existing namespaces of the organization (empty: the library only dedups with itself) |
| `GET /libraries` | Libraries the user is a member of |
| `GET /nodes/{id}/children` | List a folder (membership required) |
| `POST /chunks/lookup` | `{library, hashes}` → per hash `{chunk, state: ready \| upload}`. Requires `write`. Dedup scope: ready chunks on the library's storage, referenced by a version of the library or of a library sharing a namespace with it; pending chunks only from this library. Misses create pending chunks (organization and storage of the library). Touches every chunk. Also the keepalive |
| `POST /chunks/upload-urls` | `{chunks}` → presigned PUT URLs for pending chunks of the user's organization, in batches |
| `POST /chunks/announce` | `{chunk, plain_size, compression}` batch → reads the real size from the backend, sets `uploaded_at` |
| `POST /chunks/cancel` | `{chunks}` → deletes those no version references (row, then object) |
| `POST /files/commit` | `{parent, name}` or `{file}`, `base_version`, ordered `chunks`, `message` → creates the file if needed, the version and its `chunk_in_version` rows (organization carried down), moves `current_version`; `conflict: true` if the base wasn't current. Requires `write` |
| `GET /files/{id}/download` | Current version's ordered chunks: `{chunk, hash, compression, plain_size, url}` with presigned GET URLs. Requires membership |

Commit, in one transaction: name valid and free, every chunk ID in the library's dedup scope or from a version of the same file (code-checked), ready and of the same organization (database-checked).

Quotas (step 05), GC (step 09), member and namespace management endpoints, folders, trash and version listing (step 08) come later.

## Tests (real Postgres, temp directory backend, through the router)

Protocol:
- Upload a multi-chunk file, download it, bytes identical.
- Upload it again: every chunk comes back `ready`, nothing is uploaded.
- Edit the file: unchanged chunks reused by ID, only new ones uploaded; new version's parent is the base.
- Concurrent edits from the same base: second commit reports `conflict`, both versions exist.
- Empty file: commit with no chunks.
- Cancel deletes unreferenced chunks (row and object) but not referenced ones.
- Presigned URLs: tampered signature or expired URL refused.

Dedup scope (the code-checked invariants of `db.md`):
- Two libraries in a common namespace dedup together; a library outside it doesn't see their chunks.
- Removing a library from a namespace: its files are intact, a later upload of a block only present elsewhere is uploaded again.
- A pending chunk only matches within its library.
- A library on another storage doesn't match chunks of the first storage.
- Libraries of another organization never match.

Authorization:
- Non-members can't list, look up, commit or download; `read` members can list and download but not look up or commit.
- Commit refuses a chunk ID outside the dedup scope (e.g. guessed from another library).
- Commit refuses: taken name, invalid name, pending chunk; each with its API error.
