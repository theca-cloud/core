# Step 08: File operations

Goal: everything a file browser does, on top of the upload protocol: folders, renames, moves, copies, the trash, the version tree, and name search. Writes touch as few rows as possible; reads climb the tree when they must.

Design: `../docs/decisions.md` (File history, Conflicts, Deletion, File names, Search, Library root folder, Chunk reuse by ID).

## What's already there

- `node` (root folder per library, unique names per folder ignoring case and trashed nodes, the no-cycle trigger), `version` (tree through `parent_version`), commits with conflict detection, downloads of the current version, folder listings.
- Every check goes through `library_access` (reads: any member; writes: `can_write`).

## Folders, renames, moves

- `POST /nodes/{parent}/folders` `{ name }` → the new folder.
- `PATCH /nodes/{id}` `{ name?, parent? }`: rename and/or move, in one transaction.
    - **Within a library, a move only changes `parent`** (one row; the no-cycle trigger refuses a folder into its own subtree: `409 move_into_itself`).
    - **To another library of the same organization, a move rewrites `library` on the subtree** in the same statement (the composite FKs are checked at its end). The history moves with the files. One `UPDATE` of every node below: seconds for very large trees, and rare.
        - ponytail: if huge cross-library moves become a problem, run them as a background job (step 09) with the folder marked as moving.
    - Across organizations: refused (each organization owns and pays for its chunks).
    - The root can't be renamed, moved or deleted.
- `GET /nodes/{id}`: the node and its path (breadcrumbs), for navigating to a link.
- Names go through `theca_common::name` (NFC, rules); a taken name is `409 name_taken`, never renamed silently.
- No sizes in V1 (listings, versions): clients sum chunk sizes from a download manifest if they need one.

## Copies

- `POST /nodes/{id}/copy` `{ parent, name? }`: a file or a folder, into any library of the same organization the user can write.
    - A file: a new node and **one version with the same chunk IDs, in the same order** (reuse by ID: the source is readable, see decisions.md). No byte is uploaded or duplicated. Only the current version: the copy starts its own history.
    - A folder: its tree is walked, each file copied that way.
    - Across organizations: refused (the client downloads and uploads).

## Trash

- `DELETE /nodes/{id}`: to the trash. **Only that node gets `deleted_at`**: one row, whatever the size of the subtree.
- **A node is reachable when neither it nor an ancestor is trashed**: one SQL function, `node_reachable(node)`, climbs to the root (one primary-key lookup per level, like the no-cycle trigger). Every node access (listings, downloads, commits, moves, copies) and search go through it, like `library_access`.
- `GET /libraries/{id}/trash`: the trashed nodes, with their paths.
- `POST /nodes/{id}/restore`: clears the flag. Things trashed earlier inside it keep their own flag (still in the trash).
    - Back in its parent if reachable, otherwise **into the library's root**; the answer says where it landed.
    - Name taken: renamed `a (restored).txt`, then `a (restored 2).txt`, ...
- `DELETE /nodes/{id}?permanent=true` (a trashed node only): hard deletion of the subtree (one recursive statement), its versions and their chunk references. The chunks are freed by the GC, and the retention purge runs there too (step 09).

## Versions

- `GET /files/{id}/versions`: the tree: each version with its parent, author, date, message, and whether it's current.
- `POST /files/{id}/versions/{version}/restore`: **only moves `current_version`** to that version. The next commit, based on it, branches the tree.
- `GET /files/{id}/download?version=...`: any version, not only the current one.
- Conflicts stay as they are: the commit still wins, reports `conflict`, and the tree shows the branch. The activity feed that reports them is later.

## Search

- `GET /search?q=...&library=...`: files and folders whose name contains `q` (case-insensitive, `ILIKE` served by the `pg_trgm` index), not trashed, in the libraries the user reaches (or one of them). At least 3 characters (what a trigram index can serve), at most 50 results, each with its library and path.

## Schema changes

- `version`: `created_at`, `author` (the user; NULL once they leave: composite FK `ON DELETE SET NULL (author)`).
- Function `node_reachable(node)`.

## Tests

- Folders: create, rename, move, name rules and conflicts (case-insensitive), the root untouchable, a folder into its own subtree refused.
- Copies: a folder tree into another library shares the chunks (no new chunk rows); across organizations refused; read-only target refused.
- Moves: within a library (one row), across libraries (the subtree and its history follow), across organizations refused.
- Trash: a trashed folder's whole subtree unreachable (listings, downloads, commits, search, by direct ID); restore in place, into the root when the parent is trashed, renamed on conflict; things trashed earlier stay trashed; permanent deletion removes the subtree, versions and references (chunks left to the GC).
- Versions: history tree after edits and a conflict; download of an old version; restore moves `current_version`, and the next commit branches from it.
- Search: finds by part of a name, ignores case, skips the trash and libraries the user can't reach.
- Authorization: every write refused with read-only access; nothing reachable outside the user's libraries (`404`).
