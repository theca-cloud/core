# Step 05: Storage backends

Goal: the upload protocol runs unchanged on S3, with S3's own presigned URLs, and organizations can't exceed their quota.

Already done in step 04: the `storage` table, storage selection at library creation, the `Backend` abstraction and the filesystem backend with server-signed URLs.

Design: `../docs/decisions.md` (Storage backends, Downloads, Upload flow, Ownership and billing).

## S3 backend

- `object_store`'s S3 store (`AmazonS3Builder`), with the **`ring`** crypto provider (features `aws-base` + `reqwest` + `ring`, not `aws`; `reqwest` with `rustls-no-provider`, and `ring` installed as the `rustls` provider in `main`: `reqwest`'s `rustls` feature would pull `aws-lc-rs`), built from a `storage` row: `details` = `{"host", "region", "bucket", "access_key_file", "secret_key_file", "path_style"}`. Credentials are read from the files at backend creation, never stored in the DB.
- **Presigned URLs from S3 itself** (`Signer`), so the server never sees chunk data on S3. `Backend::upload_url` / `download_url` hide the difference with the filesystem's server-signed `/api/v1/blobs` URLs.
- `path_style`: self-hosted S3 servers usually need path-style URLs (`host/bucket/key`).
- Backends are cached per storage (built once, not per request), since the S3 client holds connections.

## Sizes, immutability and URL accounting

A presigned PUT doesn't limit size by itself, and a URL stays valid after the server is done with the chunk. So:

| Step | Client sends | Server |
|---|---|---|
| 1. lookup | `hash` + `plain_size` | Creates pending chunks with `plain_size` (`NOT NULL`, at most 8 MiB) |
| 2. upload-urls | `stored_size` + `compression` + `stored_sha256` per chunk | Declaration fixed at the first request (`stored_size <= plain_size`); a later request must repeat it exactly. Quota checked. `url_expires_at` written **before** returning the URL. URL signs `x-amz-checksum-sha256` (the backend refuses any other bytes, hence any other size) and `If-None-Match: *` (no overwrite, where the backend supports it) |
| 3. upload | exactly the declared bytes | The backend refuses other bytes. Filesystem: our endpoint checks the SHA-256 itself, and only accepts uploads while pending |
| 4. announce | the chunk | `HEAD`: the object exists **and** has the declared size; then `uploaded_at` |

- **Chunks are immutable** because the checksum fixes the content: any URL of a chunk can only ever write the declared bytes, so an overwrite can only rewrite identical bytes. `If-None-Match` adds a refusal where supported (AWS; **Garage ignores it**, verified), and a client getting `412` treats it as "already uploaded".
- **Why a checksum and not `Content-Length`**: `object_store` refuses to sign `Content-Length` (verified), and signing it ourselves would be a custom S3 client. The checksum is stricter anyway (exact bytes, hence exact size), and the announce re-checks the size.
- `stored_sha256` is kept: the future consistency check can detect bit rot in backends, not only missing objects.
- **Quota** = sum of `stored_size` over the organization's chunks (declared, pending or ready, or tombstoned until actually deleted). Checked at upload-urls (`quota_exceeded`, nothing changed). `organization.quota` (bytes, NULL = unlimited) in the migration; set in the DB by tests (admin API later).
- **Every URL is accounted for until it expires**: cancel no longer deletes, it tombstones (`deleting_at`): the chunk leaves lookups and can't be committed. Actual deletion (object, then row) is the GC sweep's job (step 09), and **only once `url_expires_at` has passed**, whatever the reason (cancel or GC grace period, which is configurable and could be shorter than a URL lifetime).
- **URL lifetime**: instance setting `presigned_url_lifetime_secs`, default 15 minutes, for uploads and downloads. `url_expires_at` = issue time + lifetime + 1 minute (clock skew between server and backend).
- `common::compress` keeps the plaintext whenever compression doesn't make it smaller, in every mode (so `stored_size <= plain_size` always holds; E2EE will relax it later for its overhead).
- Schema: `plain_size NOT NULL CHECK (0..8 MiB)`; `stored_size`, `compression`, `stored_sha256` (32 bytes) nullable but set together ("declared"), `CHECK (stored_size <= plain_size)`, "ready ⇒ declared"; `chunk.url_expires_at`; `organization.quota`. Declared at upload-urls rather than lookup so clients only compress (and later encrypt) the chunks they actually upload: compressing every chunk before the lookup would waste work on re-uploads and resumes, especially in WASM.

## Anomalies

Logged as structured `warn` events with a stable `anomaly` field, and what's needed to trace them (user uuid, organization, chunk, library, client IP where there's no user):

- announce of a missing object; size mismatch at announce;
- URL requested with another declaration, or for a chunk not pending / not writable;
- commit with chunk IDs outside the dedup scope;
- blob endpoint with an invalid or expired signature; upload to a chunk no longer pending;
- (step 09) the sweep deleting an object uploaded after a cancel.

Could be a crashing device, or an attack; repeated events stand out. The Enterprise audit log can reuse them later.

## Quota

See above: one query (`sum(stored_size)` over the organization's chunks), no counter to keep in sync. A counter can come later if it gets slow.

## Dev and CI

- **S3 server: Garage** (Rust, built for self-hosting, what many homelabs run). `docker-compose.yml` gets a Garage service, data in `data/garage`.
- `scripts/dev.sh` (still idempotent) generates its config (random secrets, `data/garage/garage.toml`) and initializes it through `scripts/garage-init.sh`: layout, a bucket, an access key in `data/secrets/`; the `S3_TEST_*` variables go into `.env`.
- garage-webui (S3 explorer) on http://localhost:3909.
- CI: a Woodpecker service can't easily get a config file, so the Garage binary is in the CI image, and `scripts/ci.sh` starts it (`ci/garage.toml`, throwaway secrets) when no `S3_TEST_HOST` is set, then initializes it with the same script.

## Tests

- **Backend contract**, run against every backend (filesystem, S3): put / get / size / delete, missing object, deleting twice, presigned PUT then GET, **a presigned PUT with other bytes (other size, or same size other content) is refused, the signed headers can't be omitted, overwriting with other bytes is impossible (a second, different declaration is refused), rewriting identical bytes changes nothing**.
- **The upload tests (`tests/upload.rs`) run on both backends**: same scenarios, the backend chosen by the fixture.
- Sizes: `plain_size` over 8 MiB refused; `stored_size > plain_size` refused; a second declaration that differs refused; announce with a missing object leaves the chunk pending.
- Quota: upload-urls refused over quota (nothing changed), unlimited when NULL, tombstoned chunks still counted, other organizations unaffected.
- Cancel tombstones (no deletion), and the chunk can't be committed or looked up anymore.
- The URL lifetime setting is used.
- Anomalies are logged (captured log events).
