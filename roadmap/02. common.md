# Step 02: `common`

Goal: the pure algorithms every component must run identically (server, native clients, web through WASM). No I/O, no network, no DB.

Design: `../docs/decisions.md` (Chunking, Hashing, Compression, File names).

## Chunking

- **FastCDC 2020** (`fastcdc` crate, `v2020` module), normalization level 1, **min 512 KiB / avg 1 MiB / max 8 MiB**, as constants.
- API over a stream of bytes, so clients never hold a whole file in memory: one function for a sync reader (native) and one for an async reader (WASM reads a `Blob` asynchronously). Each yields `(offset, length, bytes)` per chunk.
- At most one chunk (≤ 8 MiB) buffered at a time.

## Hashing

- **`xxh3_128`** of the plaintext chunk (`twox-hash`).
- `ChunkHash` newtype over `[u8; 16]`: hex display and parsing, serde as a hex string.
- Keyed BLAKE3 (E2EE libraries) is out of scope until E2EE.

## Compression

- `Compression` enum: `None`, `Lz4`, plus `Unknown` (`#[serde(other)]`) so older clients don't break on new algorithms.
- **LZ4 frame format** (`lz4_flex::frame`): the standard, self-describing format, decodable by the `lz4` command-line tool when debugging a stored chunk. A few bytes of overhead per chunk, negligible at 1 MiB.
- `CompressionPolicy`: mode (auto / always / never), entropy threshold (default 7.5 bits/byte), minimum saving (default 10%), preferred algorithm. Clients build it from their config.
- `compress(policy, chunk) -> (Compression, Bytes)`:
    - auto: Shannon entropy above the threshold → `None`; otherwise compress, keep the result only if it saves at least the minimum.
    - always / never: as named.
- `decompress(Compression, bytes) -> Result<Bytes, _>`; `Unknown` is an error.

## File names

- `Name::new(raw) -> Result<Name, NameError>`: normalizes to **NFC** (`unicode-normalization`), then validates:
    - not empty, not `.` or `..`;
    - no `< > : " / \ | ? *`, no control characters U+0000–U+001F, no bidi controls (U+202A–202E, U+2066–2069);
    - no trailing space or dot;
    - not a Windows reserved name in any case, with or without extension (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`; `con.txt` included);
    - at most 255 bytes of UTF-8 after normalization.
- `NameError` says which rule failed, so clients can explain it.
- Case-insensitive uniqueness stays in the DB (`lower()` with `C.UTF-8`): no client-side comparison, to avoid two definitions of "same name".
- Library names use the same `Name` type.

## Tests

- **Golden test for chunking**: a fixed pseudo-random input (seeded) and the exact list of boundaries it must produce. If a `fastcdc` update changed the cut points, dedup against existing chunks would silently break; this test catches it.
- Golden values for `xxh3_128` on known inputs.
- Sync and async chunkers produce identical boundaries.
- Compression: round-trip, high-entropy data stays `None`, the 10% rule, always/never modes, `Unknown` rejected.
- Names: one test per rule, including NFD input (`e` + U+0301) normalized to NFC, `con.txt`, `COM1`, a 255-byte name accepted and a 256-byte one refused (counting multi-byte characters).
- Everything builds and passes for `wasm32-unknown-unknown` (build in CI; tests run natively).
